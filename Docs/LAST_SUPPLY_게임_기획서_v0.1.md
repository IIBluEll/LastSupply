## 1. 게임 개요

### 1.1 기본 정보

| 구분 | 내용 |
|---|---|
| 가제 | **LAST SUPPLY** |
| 장르 | 운 중심 선택형 생존 탐색 / 캐주얼 익스트랙션 |
| 플랫폼 | PC 우선 |
| 개발 환경 | Unity / C# |
| 그래픽 스타일 | 2D 일러스트 기반 UI 중심 |
| 플레이 방식 | 싱글 플레이 |
| 1차 제작 목표 | 은신처 → 탐색 → 주사위 → 귀환 → 정산 → 엔딩까지 완결된 짧은 게임 |

### 1.2 게임 콘셉트

좀비 아포칼립스 이후, 소수의 생존자가 은신처에서 생활한다. 구조 요청에 필요한 무전기가 고장 난 상태이며, 제한된 시간 안에 필요한 물자를 확보하고 무전기를 수리해야 한다.

플레이어는 생존자 한 명을 외부 지역으로 파견한다. 탐색 도중 직접 수색 주사위를 굴려 자원을 찾고, 시스템이 비공개로 결정한 돌발 이벤트에 대응한다. 확보한 전리품을 지키려면 귀환해야 하지만, 누적된 소음 때문에 귀환 도중에도 위험한 상황이 발생할 수 있다.

> **핵심 경험:** 좋은 수색 결과에 기뻐하고, 예상 못 한 이벤트와 소음 때문에 긴장하며, 한 번 더 탐색할지 귀환할지 결정하는 과정.

### 1.3 설계 원칙

1. **운이 주도한다.** 수색 결과와 돌발 이벤트의 발생 여부는 확률로 결정한다.
2. **주사위를 직접 굴리는 행위를 살린다.** 수색과 이벤트 행동 판정은 플레이어의 명시적 조작으로 진행한다.
3. **선택은 최소한으로 남긴다.** 생존자/지역 선정, 이벤트 대응, 추가 탐색/귀환이 핵심 선택이다.
4. **과한 시스템을 배제한다.** 실시간 전투, 맵 이동, AI, 복잡한 제작/시설 관리 없이 완성한다.
5. **일러스트를 재사용한다.** 개별 이벤트마다 그림을 새로 만드는 대신, 지역 배경 위에 텍스트와 선택지를 변경한다.

## 2. 승리와 패배

### 2.1 기본 게임 모드: 제한 시간 탈출

- 게임에는 제한된 일수가 주어진다.
- 기간 안에 무전기 수리에 필요한 부품을 은신처로 가져와 **무전기를 수리하고 구조 요청을 완료**하면 승리한다.
- 마지막 날의 탐색에서도 조건을 달성할 수 있어야 한다.
- 기한 내 목표를 달성하지 못하거나 생존자가 모두 사망하면 패배한다.

**수치 가안:** 제한 시간 7일, 필요 부품 8개. 실제 획득량과 생존 난이도를 확인한 뒤 조정한다.

> 구조 요청 이후 추가 방어전이나 구조 헬기를 기다리는 과정은 **초기 버전에서 제외하는 것을 추천**한다. 목표 달성 시 바로 승리하면 개발 범위를 작게 유지할 수 있다.

### 2.2 생존 및 전리품

- 탐색 중 발견한 자원은 **임시 전리품**이다.
- 귀환에 성공해야 은신처 보유 자원에 합산된다.
- 탐색 중 또는 귀환 과정에서 생존자가 사망한다면 해당 탐색의 임시 전리품을 모두 잃는 방식을 추천한다.
- **귀환 버튼 = 반드시 안전한 귀환은 아니다.** 소음에 따라 귀환 위험을 내부 판정한다.

## 3. 하루 진행 구조

### 3.1 기본 루프

```text
하루 시작 / 은신처
    ↓
생존자 확인 · 치료(선택)
    ↓
생존자 1명 및 탐색 지역 선택
    ↓
외부 탐색 (여러 단계)
    ↓
귀환 성공 / 생존자 사망
    ↓
임시 전리품 정산
    ↓
승리 · 패배 조건 확인 / 식량 소비 등 하루 정산
    ↓
다음 날 시작
```

### 3.2 하루 행동(추천안)

- 하루에 **1회**, **생존자 1명**을 탐색에 보낸다.
- 탐색을 일찍 마쳐도 그날 탐색 기회는 소모된다.
- 생존자의 사망으로 탐색이 끝난 경우에도 하루는 종료된다.
- 하루에 여러 생존자를 파견하거나, 다수 파티를 구성하는 시스템은 초기 버전에서 제외한다.

### 3.3 자원 정산(가안)

**식량**
- 살아 있는 생존자 수에 비례해 하루 종료 시 소모한다(예: 1인당 1개).
- 부족한 경우 피해를 주는 안이 논의되었으나, **부족 페널티와 식량 차감의 세부 순서는 확정되지 않았다.**

**의약품**
- 탐색 출발 전에 생존자의 체력을 회복하는 데 사용한다.
- 예시: 약품 1개 = HP 3 회복, 최대 HP 초과 불가.

**부품**
- 무전기 수리 목표에 필요한 주요 자원이다.
- 은신처로 귀환해 확보한 부품만 목표 진행에 반영한다.

### 3.4 하루 종료 처리 순서(추천안)

1. 탐색 결과(귀환/사망)를 확정한다.
2. 귀환에 성공했다면 임시 전리품을 은신처 자원에 합산한다.
3. 무전기 수리 조건을 달성했는지 확인하고, 충족하면 승리한다.
4. 모든 생존자가 사망했다면 패배한다.
5. 마지막 날이라면 기한 초과로 패배한다.
6. 그렇지 않으면 식량을 소모하고 부족 페널티를 적용한다.
7. 다음 날로 이동한다.

> 식량 부족으로 인한 추가 사망과 같은 예외 상황은 규칙 확정 시 함께 정리한다.

## 4. 외부 탐색 시스템

### 4.1 탐색 단위

- 한 번의 탐색은 여러 **단계(Stage)**로 진행한다.
- **최대 5단계**를 현재 추천한다.
- 각 단계에 진입한다고 해서 **반드시 특별 이벤트가 발생하는 것은 아니다.**
- 단계에서 이벤트가 없어도 플레이어는 직접 수색을 수행할 수 있다.
- 각 단계의 처리 이후 **다음 단계 진입 또는 귀환 시도**를 결정한다.
- 마지막 단계까지 완료하면 귀환 단계로 넘어간다(권장).

### 4.2 각 단계의 진행 순서(현 시점 추천안)

```text
새 탐색 단계 진입
    ↓
[시스템 비공개] 이벤트 발생 여부 주사위 판정
    ├─ 이벤트 발생 → 상황/선택지 표시 → 필요 시 플레이어 행동 D20 판정
    └─ 이벤트 없음 → 별다른 사건 없이 진행
    ↓
플레이어가 '수색하기' 선택
    ↓
[플레이어 직접] 수색 D20 굴림
    ↓
자원 획득 또는 발견 실패 → 결과 표시
    ↓
추가 탐색 / 귀환 시도 선택
```

**중요:** 이벤트 판정 시점을 단계 **진입 시**로 할지 **수색 시작 시**로 할지는 아직 최종 확정되지 않았다. 위 흐름은 최근 논의의 **추천안 A**이며, 다른 규칙이 확정되면 조정한다.

### 4.3 수색과 이벤트는 독립 판정

| 수색 판정 결과 | 이벤트 발생 여부 | 발생 가능한 상황 |
|---|---|---|
| 발견 실패 | 없음 | 아무것도 발견하지 못하고 조용히 끝남 |
| 자원 획득 | 없음 | 특별한 사건 없이 자원을 획득 |
| 발견 실패 | 발생 | 얻은 물자는 없지만 좀비 조우 등의 사건 발생 |
| 자원 획득 | 발생 | 물자를 발견하는 동시에 돌발 사건에 대응 |

수색에 실패했다고 반드시 이벤트가 발생하지 않으며, 수색에 성공했다고 안전한 것도 아니다.

### 4.4 수색 주사위

- **수색은 자동 실행하지 않는다.** 플레이어가 명시적으로 `수색하기`를 선택한 뒤 주사위를 직접 굴린다.
- 처음에는 D20 한 개로 **미발견 / 소량 / 다량 / 희귀** 결과를 판정하는 방식을 추천한다.
- 수색 주사위는 운을 강조하기 위해 **순수 D20**으로 처리하는 안이 제안되었다. 생존자 능력치가 수색에 영향을 줄지는 미확정이다.
- 수색은 단계마다 최대 1번으로 제한하는 것을 추천한다.
- 깊은 단계에 더 좋은 보상 테이블을 적용할 수 있다. 구체적인 테이블은 미확정이다.

**수색 결과 예시 — 확정 수치 아님**

| D20 | 결과 | 예시 |
|---|---|---|
| 1~6 | 발견 실패 | 획득 없음 |
| 7~15 | 일반 발견 | 지역 주 자원 +1 |
| 16~19 | 좋은 발견 | 지역 주 자원 +2 |
| 20 | 희귀 발견 | 지역 주 자원 +3 또는 희귀 보상 |

### 4.5 이벤트 발생 주사위

- 이벤트 발생 여부는 **시스템이 보이지 않게 판정**한다.
- 플레이어에게 숫자나 주사위 애니메이션을 보여주지 않는다.
- 이벤트가 발생했다면 **사건의 상황 및 선택지**만 보여준다.
- 이벤트는 위험 사건만이 아니라 긍정적/중립적 사건도 포함할 수 있다.
- 단계가 깊어질수록 이벤트 발생률을 높이는 방안이 제안되었으나 수치는 미확정이다.

**발생 확률 예시 — 확정 수치 아님**

| 단계 | 이벤트 확률 |
|---|---:|
| 1 | 20% |
| 2 | 30% |
| 3 | 40% |
| 4 | 50% |
| 5 | 60% |

### 4.6 이벤트 행동 판정

- 이벤트에는 짧은 상황 설명과 2~3개의 행동 선택지를 배치한다.
- 선택지에 따라 판정 난이도, 적용 능력치, 성공 보상 및 실패 페널티가 달라질 수 있다.
- 판정이 필요한 선택지를 택하면 플레이어가 **직접 D20을 굴린다**.
- 일부 선택지는 별도 판정 없이 포기하거나 확정 효과를 적용할 수 있다.

**판정 공식 예시**

```text
D20 + 해당 생존자의 능력치 보정 >= 판정 난이도(DC) → 성공
그 외 → 실패
```

처음에는 성공/실패 2단계 결과만 구현하는 것을 추천한다. 대성공·치명적 실패·재굴림 자원 등은 필요해질 때 추가한다.

### 4.7 추가 탐색과 귀환

- 단계 처리 후 플레이어는 **다음 단계로 진행할지**, **귀환을 시도할지** 선택한다.
- 더 탐색하면 추가 자원 획득 기회가 있지만 이벤트 및 위험에 노출될 수 있다.
- 귀환을 선택하면 즉시 전리품이 확정되는 것이 아니라, **누적 소음에 따른 귀환 위험**을 먼저 처리한다.

## 5. 소음 및 귀환 위험

### 5.1 소음의 역할

**소음은 외부 탐색 도중 발생한 위험이 마지막 귀환까지 이어지도록 만드는 핵심 수치**다.

- 수색 주사위 자체가 소음을 증가시키지는 않는 것을 추천한다.
- 이벤트에서 선택한 행동과 성공/실패 결과에 따라 소음이 증가한다.
- 소음은 0~6 범위의 누적 수치로 두는 안이 논의되었다.
- 소음이 최대치에 도달해도 즉시 사망/강제 귀환하지 않는 방식을 추천한다.

**행동별 소음 예시**

| 행동 | 소음 변화 |
|---|---:|
| 평범한 수색 | +0 |
| 조용히 잠금 해제 성공 | +0 |
| 잠금 해제 실패 | +1 |
| 문 강제 개방 | +2 |
| 총기 사용 | +3 |

### 5.2 귀환 위험(가안)

| 누적 소음 | 귀환 처리 |
|---|---|
| 0~2 | 안전 귀환 |
| 3~4 | 일정 확률로 귀환 위험 이벤트 발생 |
| 5~6 | 귀환 위험 이벤트 확정 |

위험 이벤트의 발생 여부는 **시스템 내부에서 비공개 판정**하고, 발생한 이벤트의 행동 판정은 플레이어가 직접 굴린다.

귀환 위험 이벤트에 실패했다고 무조건 사망하는 것은 아니다. 이벤트 규칙에 따라 체력 감소 등을 적용할 수 있으며 **HP가 0이 되면 사망 및 전리품 상실**로 처리하는 방안을 추천한다.

> **미확정:** 귀환 위험 이벤트의 구체적인 종류, 소음 3~4에서의 발생 확률, 판정 실패 시 피해량.

## 6. 생존자 및 지역

### 6.1 생존자(가안)

- 초기에는 **서로 다른 능력치를 가진 2~3명**으로 충분하다.
- 예시 능력치: **HP / 전투 / 기술**.
- 기술은 자물쇠·장치·시설 관련 이벤트에, 전투는 좀비 조우 관련 이벤트에 적용한다.
- 이벤트 행동 판정에서는 능력치가 확률에 영향을 미칠 수 있다.
- 생존자 HP는 탐색 후에도 유지되며, 의약품으로 회복하는 안이 제안되었다.
- HP가 0이면 사망하고 더는 탐색에 보낼 수 없다.

**예시 캐릭터**

| 인물(임시) | HP | 전투 | 기술 | 역할 |
|---|---:|---:|---:|---|
| 마커스(전직 군인) | 10 | +4 | +0 | 전투 대응에 유리 |
| 사라(정비공) | 8 | +1 | +4 | 장치/잠금 해제에 유리 |

> 캐릭터 이름, 능력치, 생존자 수는 임시이다. 주사위 중심 게임이므로 지나치게 많은 특성이나 성장 시스템을 넣지 않는다.

### 6.2 탐색 지역(가안)

| 지역 | 주 자원 | 예상 특성 |
|---|---|---|
| 버려진 마트 | 식량 | 비교적 낮은 위험 |
| 폐쇄된 병원 | 의약품 | 장치·잠금 이벤트 가능 |
| 공업 창고 | 부품 | 상대적으로 높은 위험 |

지역마다 공통 탐색 UI를 재사용하고, **지역 이미지·주요 보상·이벤트 풀**만 바꾼다.

지역별 전용 진행 규칙이나 맵 이동 시스템은 만들지 않는다.

## 7. 이벤트 예시

### EVENT_001 — 잠긴 보관함

**상황:** 탐색 중 잠긴 보관함을 발견했다. 내부에 유용한 물자가 있을 것 같다.

| 행동 선택 | 판정 | 성공 | 실패 |
|---|---|---|---|
| 자물쇠 해제 | 기술 D20, DC 14 | 물자 획득, 소음 +0 | 보상 없음, 소음 +1 |
| 강제로 개방 | 전투 D20, DC 11 | 물자 획득, 소음 +2 | HP 감소, 소음 +2 |
| 포기 | 판정 없음 | 추가 효과 없음 | 해당 없음 |

> 수치와 페널티는 예시. 지역에 따라 보상 식량/의약품/부품을 바꿔 이벤트 데이터를 재사용할 수 있다.

### EVENT_002 — 배회하는 좀비

**상황:** 통로에서 좀비가 접근한다.

| 행동 선택 | 판정 | 성공 | 실패 |
|---|---|---|---|
| 조용히 지나간다 | D20 기반 행동 판정 | 피해 없음 | HP 감소 또는 소음 증가 |
| 싸운다 | 전투 D20 | 통과, 소음 증가 | HP 감소 및 소음 증가 |
| 물러난다 | 판정 없음 또는 별도 조건 | 해당 위치 포기 | 해당 없음 |

### EVENT_003 — 버려진 장비

**상황:** 폐허 속에서 쓸 만한 물품을 발견했다.

- 획득하거나 무시하는 간단한 선택지로 처리 가능.
- 모든 이벤트에 D20 행동 판정이 필요한 것은 아니다.
- 수색 판정 결과와 **별도의 이벤트 보상**으로 취급할 수 있다.

## 8. 실제 탐색 예시

> 다음은 시스템 흐름을 보여주는 **가상 시나리오**이며 고정 이벤트 순서가 아니다.

**상황:** 3일 차, 사라가 폐쇄된 병원을 탐색한다.

1. **1단계 진입:** 시스템의 숨겨진 이벤트 판정 → 이벤트 없음.
2. 플레이어가 `수색하기` 클릭 → D20 결과 4 → 발견 실패.
3. `계속 탐색` 선택.
4. **2단계 진입:** 시스템 이벤트 판정 → 이벤트 없음.
5. 수색 D20 결과 15 → 의약품 1개 발견.
6. `계속 탐색` 선택.
7. **3단계 진입:** 시스템 이벤트 판정 → **잠긴 보관함** 이벤트 발생.
8. 플레이어가 `강제로 개방` 선택 → D20 성공 → 추가 약품 획득, **소음 +2**.
9. 이벤트 처리 후 플레이어가 `수색하기` 선택 → D20 결과 17 → 추가 약품 획득.
10. 플레이어가 확보한 약품과 소음을 확인한 뒤 `귀환 시도` 선택.
11. 시스템이 소음에 따른 귀환 위험 판정 → 위험이 발생하지 않으면 귀환 성공, 발생하면 귀환 이벤트 해결.
12. 살아 돌아오면 임시 의약품을 은신처에 반영한 뒤 하루를 정산한다.

**핵심:** 플레이어는 수색 주사위와 이벤트 행동 주사위는 직접 굴리지만, 이벤트 발생/귀환 위험을 결정하는 내부 판정값은 보지 못한다.

## 9. UI/UX 콘셉트

### 9.1 디자인 방향

- **PC 가로형(16:9)** 기준.
- 분위기: 차분한 어두운 좀비 아포칼립스, 낡은 생존 기록/보고서 느낌.
- **왼쪽:** 장소 일러스트.
- **오른쪽:** 상황 설명, 행동 선택지, 수색 버튼.
- **상단:** 날짜, 생존자 HP, 누적 소음, 임시 전리품 등 현재 판단에 필요한 정보.
- **하단:** 탐색 진행도, 다음 단계, 귀환 시도.
- 주사위는 공통 팝업 또는 화면 내 공통 영역으로 표시.

### 9.2 메인 화면 2개 + 주사위 팝업

| 화면 | 핵심 기능 |
|---|---|
| 은신처 | 남은 날짜/자원 확인, 생존자 선택, 치료, 지역 선택, 탐색 출발 |
| 탐색 | 장소 일러스트, 이벤트 표시, 행동 선택, 수색 버튼, 결과 확인, 소음/전리품, 계속 탐색/귀환 |
| 주사위 UI(팝업) | 플레이어가 직접 굴리는 D20 연출 및 판정 결과 표시 |

### 9.3 제작 리소스 최소화

- 이벤트마다 일러스트를 따로 만들지 않는다.
- 처음에는 은신처 배경 1장 + 탐색 지역 배경 1장으로 시작한다.
- 지역 확대 시 탐색 지역 배경을 2~3장 정도로 늘린다.
- 생존자 초상화, 기본 자원 아이콘, 공통 버튼 스타일 정도만 추가한다.
- 주사위 연출은 짧게 유지하고, 수색/행동 판정에 동일한 UI를 사용한다.

**참고작**
- *Roadwarden*: 일러스트 + 짧은 텍스트 + 선택지 배치.
- *Choice of Life: Middle Ages*: 선택 후 결과를 확인하는 빠른 진행.
- *Citizen Sleeper*: 주사위로 행동의 결과를 결정하는 내러티브 경험(구체적인 주사위 규칙은 다름).
- *60 Seconds! Reatomized*: 생존자·자원·하루 단위 진행 방식.

참고작의 전체 시스템을 복제하지 않고 **UI 구성 및 특정 플레이 감각만** 참고한다.

## 10. 제작 범위 및 우선순위

### 10.1 최소 플레이 가능 버전(MVP)

**목표:** 한 번 탐색에 나갔다가 생존/사망으로 종료되는 과정을 직접 플레이할 수 있는 상태.

| 항목 | 최소 구현 |
|---|---|
| 지역 | 1개 |
| 생존자 | 1명 |
| 이벤트 | 3~5개 |
| 수색 | 플레이어 직접 D20 1회 / 단계 |
| 숨겨진 이벤트 판정 | 단계 진입 시 내부 판정(추천안) |
| 이벤트 해결 | 선택지 + 선택적 행동 D20 |
| 소음 | 누적 수치 + 귀환 위험 |
| 귀환 | 안전 귀환 또는 위험 이벤트 → 정산 |
| 화면 | 은신처/탐색/주사위 UI |

### 10.2 짧은 완성형 목표안

| 항목 | 목표 규모(가안) |
|---|---|
| 지역 | 3개 |
| 생존자 | 2~3명 |
| 이벤트 | 10~20개부터 시작 |
| 하루 제한 | 7일(밸런싱 후 조정) |
| 자원 | 식량/의약품/부품 3종 |
| 승리 | 무전기 수리 및 구조 요청 |
| 패배 | 기한 초과 또는 전원 사망 |

### 10.3 초기 범위에서 제외

- 3D 월드, 캐릭터 이동, 실시간 전투, 좀비 AI.
- 지역별 별도 맵 탐색.
- 복잡한 생존자 관계·성장·직업 트리.
- 은신처 시설 건설 및 세부 제작 시스템.
- 길고 다층적인 스토리 분기 및 방대한 이벤트 일러스트.
- 다수의 게임 모드 및 엔딩.
- 지나치게 많은 주사위 유형과 특수 상태 이상.

## 11. 남은 기획 결정 항목

코드 설계로 넘어가기 전에 아래 내용을 순서대로 확정한다. **우선순위가 높은 것부터** 정리했다.

### 11.1 우선 확정할 규칙

1. **이벤트 판정 시점:** 구역 진입 시(A, 현재 추천) vs 수색 시작 시(B).
2. **탐색 단계의 정확한 행동:** 이벤트 이후 수색을 생략하고 귀환 가능 여부, 수색하지 않은 채 다음 단계 진행 가능한지.
3. **수색 보상 테이블:** D20 구간, 단계별/지역별 보상, 자원 상한.
4. **이벤트 확률과 구성:** 긍정/중립/위험 이벤트 비율, 중복 등장 처리.
5. **소음 및 귀환 위험:** 소음 구간, 위험 발생 확률, 귀환 이벤트 처리 및 피해.

### 11.2 이후 결정할 규칙

6. **제한 시간과 무전기 부품 요구량:** 7일·부품 8개를 실제 밸런스로 확정할지.
7. **초기 자원 및 식량 페널티:** 식량 소모 시점, 부족 시 HP 감소 대상과 사망 처리.
8. **생존자 능력치 적용 범위:** 수색 D20은 순수 운인지, 행동 판정에만 능력치가 붙는지.
9. **탐색 종료/사망 예외:** 마지막 단계 처리, 귀환 중 사망, 전리품 상실 범위.
10. **반복 플레이 범위:** 단순 이벤트 랜덤화만 할지, 시작 생존자/지역 상태까지 변형할지.

## 12. 기획의 현 상태

**기본 콘셉트와 주요 플레이 경험은 정리되었지만, 상세 게임 규칙과 수치 밸런스는 아직 초안 단계다.**

현재의 가장 중요한 방향은 다음과 같다.

> **이 게임은 전략 최적화 게임이 아니라, 플레이어가 직접 수색 주사위를 굴리고 우연한 사건에 대응하면서 전리품을 가져오는 운 중심의 짧은 생존 게임이다.**

따라서 다음 작업은 클래스 구조나 코드 작성이 아니라, **탐색 한 단계의 정확한 순서와 수색/이벤트/귀환 규칙을 확정하는 것**이다. 해당 규칙이 안정되면 대표 이벤트 몇 개를 설계하고 데이터 구조 및 화면 기능을 정의한다.
